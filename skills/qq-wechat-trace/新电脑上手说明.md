# 新电脑上手说明

> 这个文件是给"把项目拷到新电脑后"看的。三步走完就能跑。

---

## 你现在手上有什么

这是一个 **DSH skill / 独立工具集**，用来导出 QQ NT 和微信 PC 的本地聊天记录。

**它不含**：你的聊天数据、密钥、导出成果——那些要另外拷（见第 2 步）。

---

## 第 1 步：装环境（约 10 分钟）

只需要装两样东西：

### ① Python 3.13 或 3.14

装完执行：

```powershell
python -m pip config set global.index-url https://mirrors.aliyun.com/pypi/simple
python -m pip config set global.trusted-host mirrors.aliyun.com
python -m pip install sqlcipher3==0.6.2
```

**验证**：

```powershell
python -c "import sqlcipher3; print('OK')"
```

> 国内源实测可用。正常情况下拿到的是预编译包，**不会触发编译**。

### ② Node ≥ 23.8

**必须 23.8 以上**——微信的 zstd 解码依赖它。

**验证**：

```powershell
node -e "console.log(!!require('zlib').zstdDecompressSync)"
```

必须输出 `true`。

> 就这两样。**不用装 npm 包**，Node 只用内置模块。

---

## 第 2 步：把三样东西拷过来

### A. 源数据库（必须）

```
QQ:   <某处>\Tencent Files\<QQ号>\nt_qq\nt_db\nt_msg.db      约 22.7 GB
微信: <某处>\xwechat_files\<账号>\db_storage\                 约 3 GB
```

**注意**：拷之前**要关掉 QQ / 微信**，否则拷到的是撕裂状态。

### B. 密钥（强烈建议带，能省掉最麻烦的一步）

```
keys\QQ_DB_KEY_<QQ号>.txt      16 字节
keys\wechat_keys.json          34 把
keys\wx_db_key_map.json        盐值映射
```

**为什么建议带**：密钥有粘性（跨重启、跨登录不变）。带着就能**跳过"扫密钥"那步**——
那步需要管理员权限 + 微信必须开着，是整套流程里最麻烦的环节。

### C. 导出成果（可选）

如果只是想看/用已有数据，把导出目录一起拷过来就**不用重新导**。

---

## 第 3 步：写 config.json

复制 `config.example.json` 为 `config.json`，改成你的真实值：

```json
{
  "qq_uin": "<QQ号>",
  "wx_account": "<微信账号目录名>",
  "home": "./work",
  "qq_data_root": "<盘>:\\...\\Tencent Files",
  "wx_data_root": "<盘>:\\...\\xwechat_files",
  "keys_dir": "./keys",
  "groups": {
    "qq": [["<群号>", "<群名>"]],
    "wx": [["<群号>", "<群名>"]]
  }
}
```

**几个坑**：

| 要填的 | 别填成 |
|---|---|
| `qq_data_root` = `Tencent Files` 这层 | ❌ 别填到 `\nt_db\` 那层 |
| `wx_data_root` = `xwechat_files` 这层 | ❌ 别填到 `\db_storage\` |
| `qq_uin` = 纯数字 QQ 号 | ❌ 别填昵称 |

**新版微信目录叫 `xwechat_files`**，老版叫 `WeChat Files`——填错就找不到。

## 第 4 步：验证

```powershell
python scripts\trace_config.py
```

它会打印**有效配置**（只打印路径，**绝不打印密钥内容**）。

看到路径都对，就可以开跑了。完整流程见 `skills/qq-wechat-trace/SKILL.md`。

## 没有 GitHub 访问权怎么办

只有**提 QQ 密钥**这一步需要联网（要从上游拉一份脚本，仓库里不带——
原因见 README 的「许可与第三方组件」）。三种解法，按省事程度排：

**① 直接带上密钥（最省事，推荐）**

QQ 的密钥跨重启、跨登录都不变。把你机器上的
`keys\QQ_DB_KEY_<QQ号>.txt`（16 字节）拷过来，这一步整个跳过。
微信的 `keys\wechat_keys.json` + `keys\wx_db_key_map.json` 同理。

**② 脚本自带 4 个镜像地址，自动回退**

`fetch_qq_key.ps1` 会依次尝试 raw.githubusercontent.com / cdn.jsdelivr.net /
gcore.jsdelivr.net / gh-proxy.com。jsDelivr 在国内一般可达。
**不用配代理、不用改任何东西**，直接跑就行。

**③ 手动下载后本地执行**

浏览器打开下面任一地址，另存为 `windows_ntqq_get_key.ps1`，然后：

```
https://cdn.jsdelivr.net/gh/QQBackup/qq-win-db-key@master/scripts/windows/ntqq/windows_ntqq_get_key.ps1
https://raw.githubusercontent.com/QQBackup/qq-win-db-key/master/scripts/windows/ntqq/windows_ntqq_get_key.ps1
```

```powershell
powershell -ExecutionPolicy Bypass -File scripts\fetch_qq_key.ps1 -LocalPath <下载的文件路径>
```

> 顺带一提：**装完之后，QQ 剥头、微信导出、zstd 解码、对账、审计全程离线**——
> 聊天记录一个字节都不会过网络。

## 跑的顺序

```
QQ 线：
  python scripts\qq_strip_header.py        剥 1024 字节头（要 22.7 GB 空间）
  python scripts\qq_export_all.py          按群导出

微信线：
  python scripts\wx_copy_shards.py         复制分片副本（微信必须关闭）
  python scripts\wx_export_shards.py <群号> 合并全部分片导出
  node   scripts\wx_fix_zstd.mjs           解 zstd 压缩（不做这步 38% 是乱码）
  python scripts\wx_verify_fix.py          对账
```

## 常见问题

**Q: 提示"找不到 xxx"**
先跑 `python scripts\trace_config.py` 看路径解析成什么了。多半是 `config.json` 填错。

**Q: 微信导出 0 条**
两个原因：① 那个群在本机没加载过（要在微信里点开它）② 分片副本没建（跑 `wx_copy_shards.py`）。

**Q: 微信密钥扫描说"微信未运行"**
开微信，**并在微信里点开要导的群**（没点开过的库密钥不会加载进内存），再重跑。

**Q: 提示权限不足**
用**管理员身份**开 PowerShell。读进程内存必须管理员。

**Q: 想改脚本**
⚠️ 别直接改 `scripts\` 里的路径相关代码。所有路径都从 `config.json` 读取，
配置问题改配置，不要改脚本。
否则下次同步会把你的改动冲掉。

## 要联网吗

**装环境要，导出不要。**

装完之后，QQ 剥头、微信导出、zstd 解码、对账 **全程离线**——这是有意设计的。

唯一需要联网的步骤是 `fetch_qq_key.ps1`（拉 QQ 密钥上游脚本）——它内置 4 个镜像地址
自动回退，国内一般可达。但你如果带了密钥文件，**这一步根本不需要**。

---

## 关于敏感文件

本仓库**已不含任何真实标识**（无 QQ号、无微信号、无真实群名、无含用户名的绝对路径）。

你自己的真实信息只应存在于这几处：

| 放哪 | 什么时候用 |
|---|---|
| `config.json` | 你本机的配置（已 gitignore，永不提交） |
| `keys/` | 密钥（已 gitignore） |
| `tools/pii_patterns.txt` | 你自己补充的 PII 特征表（已 gitignore，可选） |

**要发给别人时**：走 git 克隆或 GitHub 的 "Download ZIP"。**不要直接复制整个工作文件夹**——
`.gitignore` 只在 git 操作时生效，复制文件夹会把上面三个一起带走。
